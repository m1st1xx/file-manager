## ✨ О проекте

**Учебные файлы** — это веб-файловый менеджер, созданный специально для хранения и организации учебных материалов.

Проект позволяет каждому пользователю создать собственную структуру предметов и хранить связанные с ними файлы в одном месте.

В отличие от обычного файлового хранилища, структура проекта ориентирована именно на учебный процесс:

```text
👤 Пользователь
│
├── 📚 Предмет 1
│   ├── 📄 Лекции
│   ├── 📄 Лабораторные работы
│   └── 💻 Код
│
├── 📚 Предмет 2
│   ├── 📄 Отчёты
│   └── 📄 Методички
│
└── 📚 Предмет 3
    └── 📄 Другие материалы
```

Каждый пользователь самостоятельно определяет список своих предметов.

Это позволяет использовать приложение студентам разных курсов, специальностей и учебных групп.

# 🏗 Архитектура

Проект состоит из нескольких основных компонентов.

```text
                         Internet
                            │
                            ▼
                    ┌───────────────┐
                    │     Nginx     │
                    │ Reverse Proxy │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │    Flask      │
                    │   + Gunicorn  │
                    └───────┬───────┘
                            │
                 ┌──────────┴──────────┐
                 │                     │
                 ▼                     ▼
          ┌──────────────┐      ┌──────────────┐
          │   SQLite DB  │      │    Uploads   │
          │    users.db  │      │    files     │
          └──────────────┘      └──────────────┘
```

Nginx принимает внешние HTTP/HTTPS-запросы и передаёт запросы приложению.

Flask отвечает за:

- авторизацию;
- пользователей;
- предметы;
- работу с файлами;
- страницы приложения.

Gunicorn используется как production WSGI-сервер вместо встроенного Flask development server.

# 🐳 Запуск через Docker

## Требования

Перед запуском необходимо установить:

- Docker
- Docker Compose

Проверить установку:

```bash
docker --version
docker compose version
```

---

## Клонирование

```bash
git clone https://github.com/m1st1xx/file-manager.git
cd file-manager
```

---

## Запуск

```bash
docker compose up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Посмотреть логи:

```bash
docker compose logs -f
```

# ⚙️ Конфигурация

Конфигурационные параметры проекта задаются через переменные окружения.

Перед запуском production-окружения рекомендуется создать `.env` и указать необходимые параметры.

> ⚠️ Не добавляйте `.env` с реальными секретами в Git.

Добавьте его в `.gitignore`:

```gitignore
.env
*.db
__pycache__/
```

# 🔄 CI/CD

Проект поддерживает автоматическое обновление сервера через GitHub Actions.

После отправки изменений:

```bash
git add .
git commit -m "Update"
git push origin main
```

GitHub Actions автоматически:

1. запускает проверки;
2. подключается к серверу;
3. получает последнюю версию проекта;
4. пересобирает Docker-контейнер;
5. запускает обновлённую версию приложения.

Схема:

```text
Developer
    │
    │ git push
    ▼
GitHub
    │
    ▼
GitHub Actions
    │
    │ SSH
    ▼
Production Server
    │
    ├── git pull
    ├── docker compose build
    └── docker compose up -d
            │
            ▼
       New version 🚀
```

Это позволяет не обновлять проект вручную после каждого изменения.

# 💾 Хранение данных

Пользовательские файлы и база данных должны храниться в Docker volumes или на стороне хоста.

Это позволяет обновлять контейнер приложения без удаления пользовательских данных.

Принцип:

```text
Container
   │
   ├── Application
   │
   └── Backend
        │
        ├──────────────► users.db
        │
        └──────────────► uploads/
```

При пересборке Docker-образа:

```bash
docker compose up -d --build
```

данные пользователей сохраняются.
